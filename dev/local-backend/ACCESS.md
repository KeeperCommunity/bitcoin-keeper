# Optional private development resources

The public [app](https://github.com/KeeperCommunity/bitcoin-keeper),
[Relay](https://github.com/KeeperCommunity/Relay), and
[SigningServer](https://github.com/KeeperCommunity/SigningServer) can be cloned,
built, tested and contributed to without a Keeper invitation. The local Docker
setup in [README.md](README.md) uses only those public repositories and
disposable development identities. Production credentials are never needed.

Some assigned work may need separate private repositories, provider dashboards,
or test infrastructure. Ask the Keeper maintainer coordinating that work in your
existing private conversation. Include your GitHub username, task and the exact
resource needed. Do not post credentials or private access requests in a public
issue. If you do not have a maintainer contact, use the
[community contact](../../Readme.md#community) to reach one privately.

Maintainers review the work and grant only the needed permissions after checking
that the resource is ready to share. Approval covers the development access, not
every local command or proposed code change. Record invitation acceptance and
setup success in the internal development backlog. A contributor must use their
own GitHub identity; maintainers must not share personal tokens.

Security reports follow [SECURITY.md](../../SECURITY.md). Code acceptance,
merges, production access and releases remain separate maintainer decisions.
