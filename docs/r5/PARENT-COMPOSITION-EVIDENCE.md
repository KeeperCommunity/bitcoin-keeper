(draft #7130), preserving P1A/ZIP/strict-parser/C2 checkpoints. Its authoritative

## Original bytes and independent expectations

`parent_software_evidence.cjs` exports `validateParentSoftwareEvidence(rawFiles,
expected)` and `parentSoftwareMembers(platform)`. The exact thirteen original
Buffer members are C2's original ten plus the selected-platform immutable
`public-probe.json`, `public-features.json` and `public-product.json` wrappers.
The D aggregate is validated directly in its original format. It is never
projected, reserialized or presented to the C2 ten-member/seven-barrier API.
That original API retains its strict profile. Narrow shared object-level proof
components are reused after strict parsing of the original D bytes.

Expected input is the P1B1 independent descriptor: platform; app/controller
repository, SHA and tree; backend repository/SHA; actual execution repository,
workflow path/SHA/ref/run/attempt; and eighteen committed recovery source tuples.
It additionally requires P1A's five independently committed `workerSources`
path/hash/function-name tuples. The common utilities source must have the same
hash in both lists. Neither map nor any identity defaults to receipt fields.
IOS and ANDROID have separate authenticated controller SHA/tree/run/attempt
descriptors; their execution marker commits can differ while the app source
matches. A controller tree is never inferred from the app SHA or a selfhash.

Every original member passes the shared strict JSON parser. Aggregate, startup,
final app and each public wrapper are bounded at 2,000,000 bytes; suite metadata
at 32,768; fixture/Mongo at 8,192. The fixed thirteen caps total 12,131,072 bytes,
below a separate 12 MiB archive/inflated transport cap. D permits 2,048 recorded
budget events: an actual producer Budget host control demonstrates that this
ledger alone can exceed 262,144 bytes, so the aggregate does not use that smaller
cap. This concerns evidence transport, with no new product performance target.
