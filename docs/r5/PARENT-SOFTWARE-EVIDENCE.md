# P1A: public raw software evidence validation

This source-only package starts at `4bef0b78581ccaf4acc89053d3c7d30b04fa1338`
in an isolated branch. It prepares shared validation of existing public native
receipts. It grants no installed trust, native acceptance, release readiness or
authorization. Producer branches, failures and excluded scope remain preserved.

## Inputs and public facts

`public_software_receipts.cjs` exports
`validatePublicSoftware(metadata, expected)`, `WORKER_SOURCES` and the fixed
`PUBLIC_SOFTWARE_SCOPE`. The independently supplied expected context contains
platform, source SHA, workflow SHA/ref, run ID/attempt and the five committed
worker source path/hash/function-name tuples. Source and workflow SHAs remain
distinct inputs. Missing expected sources cannot fall back to payload hashes.

The pure validator checks successful build/startup/storage/worker predecessors,
typed root installed-byte proofs matching the built executable/APK, all five
numbered raw product samples and their eleven ordered stages, all five bounded
duration fields, counts, navigation and history observations. The separate
seven-stage controlled Retry requires its original two attempts, one dropped
request, one acknowledgement and no unexpected attempt, plus persistent count
one. Key UI requires all eleven stages, counts and unchanged scope exclusions.
Every row's installed proof must match the root. Existing exact credential,
history and Vault companion schemas still check both copies and stage proofs.

Worker evidence must contain the exact five scenarios, unchanged limitations,
five helper measurements and independently expected full-source-file hashes.
Those helper measurements never replace full-product timings. Optional PIN
diagnostic markers remain optional, and observed rejected backend calls gain no
new zero requirement. Explicit cleanup failures contradict success; absent
cleanup fields establish no disposal proof.

Only fixed identity and copied installed-proof fields leave the validator. Its
frozen result always reports installed trust UNVERIFIED and release readiness,
authorization eligibility, release authorization and execution permission false.
It performs no network, Git, filesystem or process operation.

## Canonical and consumer wiring

Canonical collection reads the five fixed committed source files at the already
verified request SHA. Path/type/encoding/size and decoded length must match.
It adds `public-raw-software-evidence` as a thirteenth scoped executed check.
Invalid public raw evidence yields NOT VERIFIED while other independently valid
subchecks remain visible. The independent trusted-origin consumer delegates its
existing raw receipt checks to the same stricter validator, retaining its own
committed-source reads and complete provenance/freshness chain. Public raw
failures now expose one fixed error code; all original rehashed-artifact and
freshness mutations remain tested.

This does not project private C/D execution into the public canonical schema.
All five parent obligations remain NOT IMPLEMENTED in this preparation, the
matrix remains incomplete, and canonical collection emits blocked readiness
without a positive attestation. Original raw artifact hashes and exact run/source
provenance remain necessary; a standalone JSON validation result is not portable
native evidence. Release authorization integration remains disabled.

and path-trigger expansion for the new dedicated public tests is coordinated in

the shared validator through their updated fixtures and negative controls.

No physical WAN, authentic historical disk or release-build performance budget
is added. Existing untested scopes remain explicit. No all-copy purge, parked
C8, storage/passcode redesign, unidentified 5.2 or physical-device obligation is
waived. No credential, protection/default-route, native scheduling, B1, signing,
upload, distribution or publication operation is performed. No personal Mac is
required.

## Verification

Compatibility fixtures execute actual product Receipt snapshots and key,
credential/history/Vault runners at fake host boundaries. They are host fixtures,
not native results. Controls cover missing/duplicate/reordered stages or samples,
wrong identities/counts/navigation, malformed durations, forged scopes/proofs,
changed committed source tuples, failed predecessors and cleanup contradictions.
Malformed committed-source API responses cannot fall back to receipt-owned
hashes. Correctly rehashed malicious original artifacts still fail validation.

Exact source checks and review outcomes are recorded at the frozen checkpoint.
Initial failures remain preserved: an unavailable TypeScript fixture import was
removed from a test-only extractor-shape check; old consumer error-code
expectations were updated to the fixed shared error; and older canonical happy
fixtures gained the missing duration fields from actual producer snapshots.
No product acceptance requirement was relaxed to address those harness changes.
