# Public policy draft boundary

`src/services/wallets/recoverable/policyDraft.ts` validates a proposed testnet 2-of-3 Mobile Key + Hardware Key + Server Key arrangement using public metadata only. Optional Inheritance Key is included **before** the whole-policy review. The module never requests a key, creates a wallet, registers a policy, signs, or funds an address. Every result is `fundable: false`.

The Mobile Key may have either public origin: `device-generated` (the default Seedless setup path, with an opaque public source reference) or `keeper-recovery-key-bip85` (an optional deterministic recreation path using the version 1 BIP85 reservation outside the existing hot-wallet and USDT ranges). The second origin is valid only when its ordinal, index, and BIP85 path agree. The first origin is **not** deterministically recreatable from Keeper's Recovery Key. Enabling RK-assisted recovery of a device-generated Mobile Key would require a separately designed and verified wrapped-backup protocol; none exists in this draft. The source reference and origin tag cannot prove that native generation, secure storage, or backup occurred.

All signers need a testnet BIP48 native-segwit account tpub with serialized depth 4 and final hardened child index `2'`. Duplicate fingerprints or tpubs, private fields, mainnet keys, and unsupported import transports are rejected. A tpub **cannot prove** its claimed earlier derivation ancestors, master fingerprint, device identity, or possession; those need device-specific checks before wallet creation.

Without Inheritance Key, the review contains Keeper's plain 2-of-3 `VaultScheme`, but no fundable wallet. With Inheritance Key, Keeper's Miniscript policy generator/compiler validates a candidate base 2-of-3 phase and delayed 2-of-4 phase. The review deliberately omits a fundable `MiniscriptScheme` or descriptor. The candidate proves only script compilation and modeled witness paths; it does **not** establish that a particular hardware firmware can display, register, or sign the complete policy. TAPSIGNER, Satochip, and Jade are blocked for this delayed-policy draft because current integrations do not verify the whole policy on-device. Coldcard remains a review candidate, with full hardware-policy compatibility still unproven. The Server Key's genuine public material and registration also remain unavailable until the held server work is reviewed.

Inheritance activation is an explicit absolute block height or median-time-past value supplied with a chain observation; this module does not choose a default duration or query the chain. The product decision on fixed versus renewed timing is pending. Keeper's existing testnet duration labels are accelerated, so no UI should present a testnet “1 year” setting as a literal year. An absolute delayed path never resets from app activity. Changing that policy later requires migration and an on-chain transfer.

Focused tests cover testnet-only inputs, public-key origin shape, duplicate rejection, optional delayed script/witness combinations, blocked hardware combinations, future locktime, and the non-fundable result. Actual receive/send, physical signer compatibility, descriptor import into another wallet, chain maturity, and server-independent heir exit still require separate tests and review.
