# Current-installed source bridge candidate

This source package completes a bounded bridge between genuine canonical/native
software evidence and the four existing protected worker adapters. It is
**unpublished source implementation**, not an installed release capability or
R4/R5 acceptance. Production installed-parent profiles remain empty. No real
operation can cross that boundary, and no signing, upload, dispatch, installation,
credential provisioning or store action was performed to prepare this package.

The supported operation scope is `SIGNED_BUILD_OR_INTERNAL_UPLOAD_ONLY`:
`ios-signed-build`, `android-signed-build`, `testflight-upload`, or
`play-internal-upload`. Every operation requires the currently installed protected
sprint source S, including uploads. Older-source uploads remain blocked. Signing
creates an artifact; the upload adapters only upload the already approved binary
to TestFlight or Play **internal draft**. They do not distribute externally, submit
App Review, or roll out production. The existing exact-artifact owner approval,
independent protected environment review, version/counter baselines, certificate,
configuration, custody and signature guards remain required.

Physical acceptance is `NOT_RUN_NOT_WAIVED`, and `public_release_ready` is false.
A signed artifact is an input to physical testing. This bounded operation does
not waive any failed test, create a hardware deferral, inherit a PR-head decision
onto a merge SHA, satisfy the existing `keeper/local-validation` hardware policy,
or grant combined R5/public-release acceptance. The repository's exact-PR/SHA
physical acceptance and owner scope-decision rules remain unchanged.

## Source and native authority

The pinned GitHub Script v8 SDK (Node 24) collects and invokes the worker in one
process. Before any repository import or Git/Python child, an embedded bootstrap
checks the fixed raw-source verifier Git blob and verifies the complete installed
driver checkout against S. Reader tokens are captured into separate scoped SDK
clients; all other global environment fields except source-tool PATH/home/temp,
locale and recognized proxy/CA configuration are removed. Existing network routing
and CA trust are preserved without changing network policy. Native/provider child environments use an explicit
build-tool allowlist plus only the selected operation's signing or upload fields.
Actions/runtime/read credentials and unrelated secrets are excluded.

The new collector authenticates the actual current worker workflow, run, attempt,
job, check ID/suite and official Actions app ownership. It then collects genuine
module-branded installed public native evidence and genuine original private D13
parent evidence. The exact original public capability, live installed source pin,
atomic manifest, private producer/source window, original ZIP bytes and all seven
canonical cases must agree. Public labels, copied objects, serialized proofs and
the earlier read-only A1 origin object cannot create this new capability.

Required Tests and CodeQL executions are authenticated by installed workflow,
source bytes, source SHA, run/attempt, complete jobs, required successful steps,
check-suite/check IDs and official Actions ownership. Only the two enumerated
reviewed `test.yml` byte hashes may use this initial policy. Their exact legacy-v2
characterization job (`Automatic backup native Realm and Relay`) supplies no v3,
native or release credit and may fail while required Lint/Tests pass. Unknown
jobs/workflow bytes, failed required Tests/CodeQL, cancelled or incomplete
executions, and incorrect ownership block. No arbitrary failing check is ignored
by a name-only filter, and PR-only status names are not postmerge native proof.

## New direct processed-SARIF security contract

The earlier A1 object is not promoted to authority. This collector independently
verifies the exact CodeQL run's original upload receipt, official SARIF processing
and exactly one official analysis with the same upload ID, source, ref, category,
analysis key and tool. It requests that exact analysis ID with
`Accept: application/sarif+json` and evaluates its original bounded bytes.

GitHub documents the returned SARIF as a subset. Therefore this policy requires
one SARIF 2.1 run, exact tool/version/category, exactly the authenticated analysis
result count, complete unambiguous rule references and security metadata, and no
suppressed or unresolved result. Missing, truncated, ambiguous or unknown content
blocks. Every security result with severity **7.0 or higher** blocks, including the
known existing 8.1 High; no baseline, dismissal or scope waiver is added. Medium,
low and non-security quality results are counted explicitly. No finding source,
location, rule ID or private code is included in the bounded result proof.

The exact-source official GitHub Advanced Security `CodeQL` checks must also be
successful. The proof explicitly records `gas_analysis_join_verified:false`:
this direct exact-analysis result evaluation does **not** invent a GAS-check to
analysis-ID join. HTTP403, unavailable APIs, multiple analyses, failed required
checks or uncertain subset completeness fail closed. Live Code Scanning read
availability is still unverified for the actual selected credential; source tests
do not prove it. The workflow requests read-only `security-events:read`.

Long collection/download work never preserves an earlier approval: required
producer/security/native/window facts are rechecked, followed by current owner
comment, permission, protected sprint/release refs and environment rereads before
the exact evidence object is branded. Uploads repeat the complete gate after
immutable artifact download. JSON and copied Symbols cannot enter the private
evidence set. The standalone old JSON collector remains unprivileged.

## Review and remaining live work

The source suite includes genuine branded public/private collectors under a
synthetic test-only installed policy, all four current-S source routes, mutation
controls for required checks/security/native revocation, original archives,
credential separation, raw-bootstrap tampering, and the actual pinned SDK with
controlled disposable responses. These tests do not install the synthetic policy
or execute an actual signing/provider operation.

Before any real operation, separately review and install the final combined
protected source and finite producer profile, run its actual canonical native and
private parent evidence, resolve the known blocking High or obtain an explicitly
reviewed policy change, verify official API access and protected-rule enforcement,
refresh store/version/custody baselines, and obtain exact owner/environment
approval for the selected operation. Physical and public-release acceptance stay
separate and incomplete. No single administrator action alone establishes these
conditions.
